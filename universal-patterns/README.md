# 通用样板独立模组

## 安装

- `gtlcore-1.2.3.3-fix4-chain-ae.jar`：替换原 GTLCore/corefix，只安装一个 GTLCore JAR。本轮新增补丁仅涉及 JEI 自动合成及 AE2 下单；已有基础修复沿用原基线。
- `gtl-universal-patterns-1.0.1.jar`：另外加入 mods，独立 modId 为 `gtluniversalpatterns`。客户端和服务端均需安装。
- 不要同时保留旧的 `gtlcore-1.2.3.3-fix4-chain-ae-universal-patterns.jar` 合并包。
- 当前适配配套 fix4 基线、GTCEu 1.4.4、Minecraft 1.20.1。没有替换本机实例，也没有启动游戏。

## 独立范围与兼容

样板物品、配方、标签、规则、工艺索引、配置界面和总成接入都由独立模组拥有。所有 Java 类迁至 `org.gtlcore.universalpatterns`，与 corefix 无重复类。通过必需的 Mixin 接入现有总成工厂，不新增重复总成方块。

保留 `gtlcore:universal_pattern` 物品 ID、`gtceu:me_recipe_pattern_buffer` 方块 ID，以及已应用配置、独立草稿、材料和配方选择的 NBT 字段，避免仅因拆包而改变存档键。实际存档迁移未在游戏内验证。

corefix 不依赖本模组；不装本模组时沿用原配方总成。卸载样板模组前应自行处理相关物品，不能把包含模组物品的存档视为无损卸载。

## 构建与验证

在项目根运行 `python enhancements/build.py` 和 `python universal-patterns/build.py`。两者分别编译打包。独立模组直接针对既有 fix4 基线编译，不需要 corefix 中的样板补丁。

离线检查包含：拆包后的生产方法草稿回归、工艺/规则回归、布局检查、JAR CRC、无重复类、corefix 修改类白名单和总成工厂目标签名。未启动游戏验证 Forge 实际加载。

支持源码来自现有 fix4 配方总成实现；许可证保留在 JAR 的 `META-INF/licenses`。

## 1.0.1 兼容性复查

总成接入改为按 `me_recipe_pattern_buffer` 注册名替换工厂，不依赖编译器生成的 lambda 编号。启动时校验该注册命中恰好一次，避免接入丢失后继续加载错误机器实现。只需将 1.0.0 样板包替换为 1.0.1，不同时安装两版；corefix 未改变。

使用 ASM 对旧合并包和独立包的真实字节码做归一化比较：物品 ID 初始化、物品注册、配置与草稿读写、总成存档读写方法一致；持久化字段相同。另用旧格式手工 NBT 测试保留配置与草稿、撤销和应用。测试不启动 Minecraft，不等同于完整 Forge 加载或真实世界迁移实测。


## 目标容器预放不消耗物品（2026-11-17）

- 普通 AE 加工样板：在样板编码终端通过 JEI 填充 GT 配方时，按住 Alt 点击填充。只排除注册配方明确标记为不消耗的物品/流体（含对应虚拟凭证），仍编码为普通加工样板，输出和配方类型元数据沿用原流程。编码结果可用于所有接受标准 AE 加工样板的样板供应器或样板总成；目标机器/输入容器应预放所需实物。已有样板可放回编码终端，以该方式重新填充并编码。
- 通用样板（1.0.11）：点击原料区域中不消耗原料的图标，在小面板选择“虚拟供应 / 目标容器 / 直接忽略”，应用修改后生效。图标下只显示当前方式。设置归属于这张卡，关闭界面保留草稿，撤销丢弃草稿；移动/重载保留已应用配置。
- 同一配方同时消耗的同名材料不会被删除；概率消耗不视为不消耗；混合替代项不整体删除；流体按 NBT 精确区分。
- 按物品/流体及完整 NBT 区分供应方式，同一张卡中相同原料共享该项设置，不影响其他原料。旧版整卡开关保留为未单独设置项目的默认值，旧逐项布尔设置无损读取为虚拟/容器。多个卡重复收录同一配方时仍应避免设置冲突。
- “直接忽略”独立记录为第三种模式，样板不请求该项供应、不生成虚拟凭证、不注入对应虚拟电路；不能取消机器实际配方条件。“目标容器”明确要求玩家预放实物。当前总成执行层对两者均不注入虚拟原料，普通与扩展供应器仍需按机器实际要求预放不消耗原料。
- 通用卡现在可以直接放入 AE2 普通样板供应器、ExtendedAE 方块式/面板式扩展样板供应器，以及普通/库存型通配符样板总成；专用配方样板总成保留完整编辑界面。按用户要求，普通样板总成及其库存/扩展变体不增加通用卡接入。旧通配符样板的注册与展开算法不变。
- 无输入加工样板仍遵循 AE 限制：若 Alt 移除后为空，保留原投料并提示，避免生成无效样板。客户端和服务端均需更新独立通用样板 JAR（界面同步增加字段）。
- 催化剂预放不等于 AE 能检测任意目标容器缺失。机器仍按实际注册配方验证，缺少实物会等待，不会凭空豁免。

## 供应器直接接入（2026-11-17）

- 一张实体卡发布多个真实注册配方；实际投料继续使用 AE 原生加工样板路径。不会将卡片替换成第一张展开样板，不写入或删除卡片配置/草稿。
- 仅已应用配置参与发布，排除项/黑名单优先，保留同材料的指定配方。概率耗材和不确定主产物不会被直接发布。
- 普通及扩展供应器没有总成的虚拟催化剂能力；不消耗输入由目标机器/容器预放，供应器仅发送消耗输入。专用总成及通配符总成系列支持自动虚拟供应，选择“目标容器提供”时不发布虚拟凭证；设置不因移动卡片而丢失。
- 配方索引按类型共享缓存，配置缓存最多 256 项；数据包刷新后重新发布，删除样板沿用各容器的原生清理路径。
- 通配符总成中的通用卡缓存按完整加工样板身份保存，避免相同产物的不同配方在重载时覆盖。旧通配符卡仍使用原保存格式。
- 通用卡编辑功能已并入原通配符总成系列：主界面原槽位放入卡片，打开侧栏“通用样板”即可编辑。普通版/库存版共用同一编辑组件，支持 JEI 拖入、属性/标签、多条规则、与或表达式、材料三态、指定配方、收录原因、应用与撤销。只操作这张卡的配置，旧通配符样板仍用原界面编辑。
- 原总成主界面的样板槽、库存配置、网络状态和缓存展示保留；原注册 ID、名称、标签、合成配方、等级、机器能力、任务资源不修改。旧专用配方总成保留用于已有存档兼容，不要求更换已经放置的机器。
- 配方执行按类型+配方 ID 校验，物品/流体共用同一约束；相同输入也不会误执行另一条注册配方。虚拟供料每 20 tick 检查相关凭证，忽略与所收录配方无关的凭证变化。
