# Universal Recipe Patterns · 通用样板

一张 AE2 通用样板可以同时发布多条加工配方。用工艺、材料或输入与输出样本筛选真实注册的配方，选择要收录的变体，再交给样板供应器或样板总成自动加工。**目前仅支持 GregTech Leisure。**

## 下载与安装

1. 使用 [GregTech Leisure 1.4.5.4](https://www.curseforge.com/minecraft/modpacks/gregtech-leisure/files/9322925)（Minecraft 1.20.1、Forge 47.x、GTCEu 1.4.4、AE2 15.4.10）。通用样板需要 Java 21 或更高版本。
2. 确认 `mods` 中只有一个 GTLCore JAR，并按下表选择通用样板版本。整合包内置 GTLCore 为 `1.2.3.3`，[官方另发的补丁版为 `1.2.3.3-fix4`](https://github.com/GNSW/GTLCore/releases/tag/version-1.2.3.3-fix4)。
3. 从 [1.0.36 发布页](https://github.com/winterd77/Universal-Recipe-Patterns/releases/tag/v1.0.36) 下载 `universal-recipe-patterns-1.0.36.jar`，放入 `mods`。升级时移出旧版通用样板 JAR（旧文件名可能以 `gtl-universal-patterns-` 开头）。联机时客户端和服务端都要安装同一版。

## 使用

1. 用一个 AE2 空白样板无序合成通用样板。
2. 手持样板对空气右键，选择工艺，再按材料、规则或输入与输出样本筛选配方。关闭界面会保存草稿。点击「应用」才会更新向网络发布的配方。
3. 将样板放入受支持的 AE2 普通样板供应器、ExtendedAE 扩展样板供应器、GTL 通配符样板总成或配方样板总成。使用「目标容器」供给不消耗原料时，提前在机器端备好所需物品或流体。

1.0.33 新增注册配方分组。可直接搜索「混沌炼金」等已翻译的工艺名称。已有工艺优先匹配，其余可编码的注册配方按配方类型、产物形态或带等级和材料的部件名称归组。绑定工艺后可查看组内配方，并单独选择变体。

1.0.36 在「同类配方」标题旁增加组内搜索框。输入材料名、产物名或配方 ID 即可筛选整个分组，清空可显示全部。筛选后可继续逐条勾选。

对有多个合法物品的消耗原料，点击原料图标，再点「替换物品」。鼠标悬停可看候选物品的注册 ID。选中后会记为当前玩家的默认选项，之后配置其他卡时，同一组候选会沿用这个选择。点击「保存并应用」更新当前卡的 AE 投料。选择窗口里的「清除此偏好」可恢复默认候选并清除对应个人记录。

点击同类配方右侧的复选框，可单独收录或排除该条配方。手动排除的变体会单独显示，便于重新勾选。点击「应用」后更新 AE 发布的配方。

新绑定的样板按实际配方的电路编号、辅助流体和不消耗原料区分加工路线。旧样板保留原有收录范围。要把旧卡限定为其中一路，请选中该条配方，点「更多操作 → 限定此路线」，再「保存并应用」。

「更多操作」提供三项设置。

- **预期产物**默认只让 AE 等待主产物。选择「全部产物」后，其他确定产物也计入预期。手动忽略的产物继续跳过，概率副产物按原配方生产。
- **新卡供给**保存当前玩家的不消耗原料供给偏好。新卡在玩家合成时继承，自动合成的空白卡在首次配置时继承。
- **本卡供给**可单独调整一张卡。可选虚拟供应、目标容器、直接忽略、直接供应。自动模式下，新卡默认直接供应编程电路，其他不消耗原料默认虚拟供应。单项原料设置优先，可点「跟随样板默认」撤销覆盖。

在「更多操作」或产物详情中打开「样板倍率」，按需填写正整数并应用。

- **整批倍率**决定 AE 每次发送几份消耗原料。物品、流体、预期产物和手动追加的数量都按份数计算。编程电路和不消耗的催化剂按一份配方的需求准备。
- **机器产出倍率**应填写机器当前的实际增产倍数，只额外放大常规产物。逐刻输出、循环容器返回物和手动追加数量只随整批倍率变化。
- 例如，单份消耗 2 个原料、产出 1 个成品时，整批设为 4、机器产出设为 15，AE 每次发 8 个原料，等待 60 个成品。旧卡沿用原有产出倍率，整批默认 1。

## 从源码构建

`universal-patterns/src` 包含源码和资源。构建脚本使用 Windows、Python 3、JDK 22 和 Prism Launcher 的 GregTech Leisure 1.4.5.4 实例及库。编译目标为 Java 21。

- 把官方 `gtlcore-1.2.3.3-fix4.jar` 放到 `build/`，或用 `GTLCORE_JAR` 指定上述两个 GTLCore 版本之一的 JAR 路径。
- 把 JetBrains 注解 JAR 放到 `build/annotations.jar`，或用 `GTL_ANNOTATIONS_JAR` 指定路径。
- 在 `build/gtlcore-wireless/` 准备对应版本的 `forge-mojmap.jar`、`client-mojmap.jar` 和 `srg-mojmap.tsrg`。
- 在仓库根目录运行 `python universal-patterns/build.py`，输出到 `dist/universal-recipe-patterns-1.0.36.jar`。
